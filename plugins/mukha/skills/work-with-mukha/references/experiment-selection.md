# Choose the experiment that resolves the blocker

Use the current source and live job state, not the latest prose paragraph alone.
Keep one active scientific question and a short decision ledger. A question can
span turns; finishing a turn need not shrink it into a smaller accomplishment.

Prefer a next action that has all of these:

1. It addresses an explicit requirement or dependency of the final fly.
2. Its outcome distinguishes named alternatives, including a plausible failure.
3. The observation is reachable with existing or justified new instrumentation.
4. Its cost is bounded by actual resources and the data needed for that decision.
5. It leads to implementation, a rejected hypothesis, or a precise external-data
   request. A count/checksum alone is only a prerequisite when no decision follows.

Reuse the project's protocol files. A sufficient experiment note is: hypothesis;
fixed graph/model/inputs; changed factor; measured quantity and units; controls;
predeclared acceptance; cost/checkpoint boundary; success/failure next action.
Do not create a new mandatory report format for trivial reversible changes.

Examples for this project:

- **Synapse extraction:** finish all batches, validate per-pair counts and ROI
  resolution, then decide whether the selected plasticity model can localize its
  teaching signal. A few more downloaded batches are progress but not this result.
- **Local plasticity:** fit a declared source protocol and test timing reversal,
  stimulus specificity, persistence and learning-off. Numerical agreement with
  one's own Python implementation alone does not establish physiological transfer.
- **Body loop:** validate one full sensory-to-contact causal chain on the complete
  CNS with declared hypotheses, then extend cockpit controls. Another isolated
  pulse fixture needs a concrete unresolved mechanism to justify it.
- **Performance:** measure an integrated trace, choose the actual limiting stage,
  preserve the output contract, test long/adapted regimes and compare complete
  cycle time. More launch sweeps without a bottleneck hypothesis are low value.

When an experiment is negative, keep its evidence and reject only the hypothesis
actually tested. Do not infer that all biological mechanisms fail, and do not
quietly tune on the assessment set then report a new independent validation.
When blocked on data, exhaust relevant existing sources and articulate exactly
which observable/identity is missing. Continue independent necessary work where
available; do not create endless inventories as a substitute.

Use skills at the relevant boundary. Read once, use the guidance, then record the
changed decision naturally in the experiment/result. No skill-count KPI or
ceremonial rereads. If the user asks whether plugins are being used, inspect the
specific session's tool calls and distinguish requested reads from verified
application. Installed plugin metadata alone is insufficient.
