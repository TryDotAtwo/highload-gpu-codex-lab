# Work with Prism

For this writing workflow, Prism is required for preparation and substantial editing of articles, books, reports, and LaTeX manuscripts. Use an actual project and its assistant for substantive reasoning, explanation, review, or revision. A local read, an upload alone, or mentioning Prism is not that work.

## Establish the project and authority

Read [workflow details](references/workflow.md) and [product sources](references/product-sources.md). Identify the intended project, authorized source set, scope, and approved baseline. Preserve the requested final format. If the source is not LaTeX, choose a useful review representation in Prism while preserving the requested deliverable format. Ask only when that choice would materially change the requested content, format, or scope.

Use the available authorized browser or connector. State whose browser is in use. On the user's computer, use only the approved standard Chrome route; do not substitute desktop mouse, UI Automation, Playwright, or another access route. Coordinate a single operator for a shared browser/project. Observe actual controls; documentation and old receipts do not prove current UI availability.

At a new session inspect available models and reasoning controls. Prefer 6.1 Sol with Very high if actually offered. Otherwise use an explicitly verified available model within the user's fallback permission, or ask if the requested model was mandatory. Record the observed choice; never invent a model button or claim 6.1 from a preference alone. Do not repeatedly interrupt a running generation to recheck the selector.

## Run a source-bound collaboration

1. Freeze the input snapshot with file paths, byte counts, and SHA-256 hashes. Keep chapters/sections modular and figure sources editable. Obtain any required transmission permission before uploading.
2. Open the real project and assistant. Supply the exact small relevant sources plus claim constraints and a bounded substantive question. Ask it to identify the source version it reviewed. Save the request and final response; private reasoning is not a deliverable.
3. The main agent owns the manuscript. Evaluate each suggestion against sources and user intent; record accepted, changed, and rejected suggestions. Preserve uncertainties. Passing plugin principles to Prism does not install the plugin there.
4. Bind review to its actual input snapshot. After changes, record the final snapshot and the checked diff. New substantive text needs review appropriate to that new text; it cannot inherit an earlier full-review claim.
5. Compile at section/chapter checkpoints and at final integration. Inspect every changed figure at final scale and every page of the final deliverable. Apply write-visual-research-papers for scientific evidence and visual QA. Record actual QA scope and final source/PDF identities.
6. When synchronization is requested, verify saved content by readback/export. Keep drafted, reviewed, edited, saved, compiled, downloaded, visually checked, and published as separate statuses. Preserve approved artifacts; publication/sharing needs its own authorization.

## Stop honestly when blocked

An authorization denial stops that dependent action; do not bypass it. For transient failures, diagnose the observed cause and make a bounded justified retry, then report the exact blocker and minimum next step. Never loop until access appears. Safe local preparation may continue, labeled as preparation. Do not claim the requested Prism workflow complete without real project-agent work and the required evidence. A timed-out download is not a downloaded or independently inspected PDF. After real Prism work on the relevant source version, a source-bound local build and QA may provide the final PDF unless the user specifically required a remote artifact.
